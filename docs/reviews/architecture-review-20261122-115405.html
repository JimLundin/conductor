Keep diffs; cut historical undo

crates/host/src/session.rs:315 · crates/host/src/checkpoints.rs:262 · crates/client/src/host_view.rs:701 · crates/ui/src/checkpoints.rs:1

Problem
One rewind promise coordinates native conversation history, filesystem state, recovery phases and the Host fold.
Cut / retain
Remove UndoTurn and native rewind; retain checkpoints, GetDiff, restart recovery and ordinary Continue.
Give up
Restoring both files and conversation in one action. A corrective new turn keeps the earlier context.
Deletion test
Ten of the session module’s twenty Flow variants support undo. Removing the promise removes that coordination; retaining rewind under a different control merely moves it.
Depth & seam
The two provider adapters earn their seam. Narrow their responsibilities so the retained session interface has less history machinery to expose.
Tests
Delete rewind/reconciliation tests; retain snapshot retries, immutable diffs, replay, Continue and workspace safety tests at their existing interface.
  • Locality: checkpoints capture changes
  • Leverage: diffs retain review value
  • Interface loses UndoTurn
Revises the built diff-and-undo behavior in architecture §5.3. Recovery is necessary while undo remains; this is a feature cut, not permission to weaken recovery.

Verified in Flow at session.rs:315–340 and undo execution at :1328. The checkpoint module also serves retained behavior: do not delete it wholesale.

Cut automatic finishing and branch landing

crates/host/src/finish.rs:178 · crates/daemon/src/session.rs:269 · crates/host/src/workspace/plan.rs:766 · crates/home/src/issue/operation.rs:480

Problem
Finishing couples a Summary turn, process lifetime, branch landing, push outcomes and issue status in eleven workflow states.
Cut / retain
Remove FinishSession and its automatic summary, landing and issue updates; keep worktrees, checkpoints, issue starts and safe session removal.
Give up
One-click summary, merge, push and move-to-review. The owner or agent performs those actions explicitly.
Deletion test
The dedicated finish module and finish-only orchestration disappear. Git integration work moves to the owner; it is not eliminated if automatic landing is still expected.
Depth & seam
The Workspace plan is already deep and has a real Git adapter. Cut finish-only operations from its interface while preserving its useful seam.
Tests
Retire summary-timeout, finish retry and landing receipt tests; retain issue-start branch readiness, branch retention and safe removal checks.
  • Locality: session lifetime is simpler
  • Leverage: ordinary messages carry summaries
  • Interface loses FinishSession
Conflicts with the active flow spec’s status-role automation task and Finish workflow. Accepting this cut changes that product commitment.

Dedicated footprint: 479 lines before trailing tests in host/finish.rs, plus finish-specific shell and Git operations. RemoveSession still snapshots and pushes the session branch; cutting FinishSession alone does not remove every push.

Make the Conductor app an issue reader

crates/ui/src/issues.rs:28 · crates/app/src/issue.rs:28 · crates/daemon/src/home.rs:398 · crates/home/src/issue/operation.rs:123 · crates/home/src/flow/command.rs:150

Problem
Issue writing now has a flow-driven CLI path and a fixed-model app/daemon path, with offline edit delivery reaching across the wire, storage and session automation.
Cut / retain
Remove app creation/editing and all automatic issue mutations. Retain issue reading, project discovery, instructions and the Issue brief; keep the home CLI in this workspace.
Give up
Issue editing from the phone and automatic status/summary updates. Authors use the existing home CLI, with commit/push handled by their normal workflow.
Deletion test
Pending issue edit storage/replay disappears only after the app editor, start-status writes and finish writes all go. Removing the editor alone saves less.
Depth & seam
Concentrate writing in the flow module; the existing filesystem/Git adapter remains at the reading seam. A smaller interface improves locality without moving code to another repository.
Tests
Delete remote editor and pending-edit replay tests with their callers; keep CLI validation, issue parsing, host selection, Issue brief and instruction tests.
  • Locality: one issue-writing model
  • Leverage: flow validation stays shared
  • Interface loses two editing commands
Reopens the active flow spec’s app scope and decision that the app calls the home crate. It preserves the home ADRs’ file tracker and flow-as-data choices; those do not require deleting the CLI or its interpreter.

The CLI is implemented on this baseline (312ac40). The existing issue-model coupling spec records about 120 uses across ten files; that is evidence of coupling, not a deletion estimate. Its older compatibility concerns are superseded by AGENTS.md’s disposable-data policy.

Choose effort once per session

crates/host/src/session.rs:661 · crates/ui/src/session.rs:734 · crates/claude/src/runtime.rs:235 · crates/proto/src/lib.rs:499

Problem
One adjustable setting reaches a wire command, durable event, optimistic picker, next-turn state and a provider-specific live settings operation.
Cut / retain
Remove user changes to effort after session creation. Retain initial model/effort selection, display, ordinary Continue and model compatibility checks.
Give up
Raising or lowering reasoning effort while keeping the same conversation; a different choice requires a new session.
Deletion test
The mutable-setting command, event, picker and Claude live retuning disappear. Initial settings and Codex turn configuration remain, so savings are modest.
Depth & seam

Tests
Delete change-between-turns and picker-rollback tests; retain initial selection, model compatibility, provider launch and resume coverage.
  • Locality: effort chosen at launch
  • Leverage: one choice spans turns
  • Interface loses SetEffort
Revises effort-between-turns behavior. Valuable only if in-conversation retuning is worth less than its ongoing surface.

The live change is implemented and covered by daemon/tests/e2e.rs:5850; it is not dead code. Resume after a credential/model change must still apply compatibility rules; that internal adjustment is separate from the removed user control.

Automatic checklist notes are already gone. Candidate 03 includes the remaining issue-write cuts; it does not require removing branch landing if landing can stop writing issues. Candidate 02 removes the whole finishing workflow. Their savings overlap.

What still earns its place

Both provider adapters, worktree isolation, replay after disconnect, approvals/questions, private account homes and multi-host pairing directly support supervising sessions. Their complexity is not evidence that they are shallow modules.

How to judge a cut

Accept the lost behavior first. Then delete its implementation, protocol variants, controls and obsolete tests together. Fewer source lines alone do not establish depth; the retained interface should require less knowledge from callers.

Top recommendation

Start with historical undo.

Candidate 01 removes coordination across both provider histories, Git recovery and the Host fold while retaining diffs, worktrees and ordinary Continue; it is independent of the active issue-flow decisions.
