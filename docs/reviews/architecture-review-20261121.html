Solution

Problem

Solution

Both stores are encrypted and have file-permission protection. The gap is key custody: migrating store.key does not migrate fleet-store.key.

Problem

Fleet pairing and enrollment bypass the UI model: the app shell owns state, issues commands and interprets replies alongside its rendering.

Solution

Move fleet workflow decisions and drafts into the existing UI model; leave native browser key access, signature verification, storage and rendering in their adapters.

ui receives FleetHosts after app-owned reconciliation; it cannot exercise the full pairing, invitation or browser-approval workflow through its normal interface.

  • Locality: fleet flow decisions concentrate
  • Leverage: desktop and phone agree
  • Depth: UI tests exercise whole flows

Scope and limits. Findings target the freshly fetched GitHub main at 22a49a4, not the older local task checkout. The review traced source paths and inspected test scenarios; it did not run fault injection, provider sessions, host loads or real-device acceptance. The Git return scenario is a prediction to verify. Credential removal ordering and separate fleet key custody are directly visible in the implementation.

Design anchors: D1–D9:39, fleet behavior:1, credential recovery:1, planned app direction:236, existing verification:1. No proposal reopens the settled root-host or subscription-sharing decisions. Existing provider verification does not establish every mobile or cross-host acceptance case.
