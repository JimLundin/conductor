Keep checklists local to their session

crates/proto/src/task_board.rs:9 · crates/host/src/session.rs:649 · crates/host/src/progress.rs:55 · crates/daemon/src/progress.rs:58

Problem
The handoff interface asks the receiving agent to preserve an exact text label, while three readers reconcile ownership independently of the native checklist.
Cut
Remove task handoff and automatic checklist-derived issue notes; retain each agent’s checklist as session information.
Give up
Tracked transfer of a task to another session, and automatic “Done: …” issue notes. Ordinary messages and explicit issue notes can remain.
Deletion test
Ownership reconciliation and note delivery disappear only when both capabilities go; hiding the controls leaves their implementation intact.
Depth & seam
The two provider adapters already supply checklist snapshots. Keep that real seam; a smaller session interface gives depth without a second task model.
Tests
Retire handoff ownership and progress-delivery tests; keep provider checklist mapping, display and replay tests. Retain checklist undo coverage if candidate 05 stays.
  • Locality: checklist state stays per session
  • Leverage: existing provider snapshots suffice
  • Interface loses HandoffTask

Dedicated footprint: 323 source lines in TaskBoard and the two progress modules, before trailing tests; routing, storage and presentation hooks add more. Label formatting:1164 and label parsing:77 show the coupling. Stable TaskId/holder removal needs a separate check of child checklist and rendering uses.

Revises documented task handoff and progress-note behavior in roadmap:281 and home flows:196. Both are implemented; this review makes no claim that they are unused.

Stop transferring conversations between hosts

crates/daemon/src/movement.rs:30 · crates/daemon/src/movement/package.rs:41 · crates/host/src/movement.rs:141 · crates/runtime/src/plugin.rs:73 · crates/ui/src/movement.rs:26

Problem
One movement command adds a separate wire protocol, native transcript import/export, Git bundle validation and recovery of uncertain ownership.
Cut
Remove session migration. Keep running independent sessions on several hosts; use an issue’s branch and notes when starting a fresh conversation elsewhere.
Give up
The same native conversation continuing on another machine, plus direct branch transfer for projects without a remote. A fresh session is a different capability.
Deletion test
The movement implementation vanishes if session ownership never transfers. Rebuilding a transfer tool elsewhere would only relocate it.
Depth & seam
Remove the transcript-transfer seam and its two provider adapters; retain the two adapters at the ordinary provider seam. The host module’s interface gains depth through stable local ownership.
Tests
Retire movement protocol, package, ownership and transfer UI tests. Keep multi-host connection, native Continue, isolation and checkpoint tests.
  • Locality: ownership remains on one host
  • Leverage: reuse issue continuity
  • Interface loses MoveSession
Reopens F7:1684 (bundle transport) and F8:1685 (matching pins for moves). The 3,219-line footprint and cross-host recovery justify discussing the capability itself; these decisions still govern it if retained.

Largest directly identified footprint in this review. The count excludes distributed hooks in the log, registry, provider plugin and client. It is an affected source footprint, not a guaranteed deletion count.¹

Drop automatic finishing and branch landing

crates/host/src/finish.rs:178 · crates/daemon/src/session.rs:1 · crates/host/src/workspace/plan.rs:1065 · crates/proto/src/lib.rs:566

Problem
Finishing combines a summary turn, a ten-minute deadline, process lifetime, branch landing, push outcomes and issue status changes.
Cut
Remove FinishSession and its automatic summary/landing workflow. Keep workspace creation, isolation, checkpointing and removal.
Give up
One-click summary, merge, push and move-to-review. Completing the work would use explicit agent instructions or the owner’s existing Git workflow.
Deletion test
The 479-line finish module and finish-specific orchestration can go. Git integration work moves to the owner; it is not eliminated if automatic landing is still required.
Depth & seam
The workspace plan is already a deep module with a real Git adapter. Narrow its interface by removing finish-only operations, rather than collapsing the useful seam.
Tests
Retire finish-state, timeout and landing-specific tests. Keep workspace ownership, safe removal and any branch-readiness tests still needed by issue starts.
  • Locality: sessions manage agent lifetime
  • Leverage: reuse ordinary messages
  • Interface loses FinishSession
Revisits the Finish workflow:183 and automatic finishing:756. Candidate 04 requires removing the issue writes here too; deleting only the summary turn would not remove landing or pending-edit complexity.
04
Worth exploringlocal-substitutable

Make Conductor’s issue context read-only

crates/home/src/issue/operation.rs:1 · crates/daemon/src/home.rs:327 · crates/proto/src/issue.rs:1 · crates/ui/src/issues.rs:1 · crates/app/src/issue.rs:1

Problem
Issue meaning reaches the file parser, wire, editor, session status rules and durable pending edits; the existing tracker already records this coupling.
Cut
Remove app issue creation/editing and all automatic issue mutations, including start-status changes, progress notes and finish updates. Retain useful issue reading and the issue brief.
Give up
Managing issues from Conductor, offline editing, and automatic status/note updates. The planned home CLI must be usable before it can replace that workflow.
Deletion test
Only removing every mutation caller makes pending-edit persistence and replay deletable. Moving the flow module into another repository would not reduce total code by itself.
Depth & seam
A read-only home interface improves locality of issue writing in its owning module. Keep the filesystem/Git adapter at the read seam; do not invent a second adapter just to justify an abstraction.
Tests
Retire editor and offline mutation/replay tests after their callers are removed. Keep file parsing, project resolution, instruction composition and issue-brief tests.
  • Locality: issue changes have one owner
  • Leverage: issue brief remains useful
  • Interface loses two authoring commands
Reopens the home’s flow-interpreter decision and tracker decision to the extent they put interpretation and authoring inside Conductor. The owner also settled that the home CLI lives in this workspace and the app calls its crate; that is a real commitment, not accidental bloat.

Existing issue: Decouple the issue model records about 120 uses across ten files. Main already has the flow loader and graph reader; their presence is intentional work in progress, not evidence of unused code.

Keep diffs; remove historical undo

crates/host/src/checkpoints.rs:10 · crates/host/src/session.rs:1483 · crates/host/src/workspace/plan.rs:564 · crates/ui/src/checkpoints.rs:1 · crates/proto/src/lib.rs:498

Problem
Undo synchronizes provider history, filesystem state, durable recovery phases and the client’s view of later turns.
Cut
Remove UndoTurn and historical rewind. Keep per-turn snapshots and GetDiff, so the owner can still review what changed.
Give up
One-click restoration of files and conversation together. A compensating change in a new turn does not erase previous context.
Deletion test
Native rewind and undo recovery disappear when rewind is no longer promised. Snapshot reservation, retries and safe workspace ownership still earn their keep.
Depth & seam
The Claude and Codex adapters implement different rewind behavior at a real seam. Cutting that capability narrows the session interface; the remaining checkpoint module gains locality, not merely fewer files.
Tests
Retire native rewind, history-trimming and undo recovery tests. Keep snapshot retry, immutable diff, restart/Continue and workspace safety coverage.
  • Locality: checkpointing only captures changes
  • Leverage: diffs retain review value
  • Interface loses UndoTurn
Revisits the built diff-and-undo behavior:615. Keep every current recovery guarantee if undo remains; simplifying recovery without cutting the promise would weaken correctness.

What earns its keep

Two provider adapters make the provider seam real. Managed CLI installation hides packaging, platform and version checks; deleting it mostly transfers that work to deployment.

Multi-host supervision, approvals, questions, native Continue, workspace isolation and reconnection directly support the documented purpose of Conductor.

Lower-return cuts

Nested sub-agent transcripts and in-app Claude token creation are possible smaller cuts. Child approvals still require routing, and token creation would move to the owner’s terminal. Neither is as clear a first cut as session-local checklists.

Account breadth and phone sign-in implement explicit owner decisions. Code volume alone does not justify removing them.

Top recommendation

Start with 01 · Local checklists.

It removes a second task-ownership model and its issue-writing observer while preserving visible progress inside every session. If the priority is the largest scope reduction, explore 02 · Session migration next.
