Why it's shaped this way

  • A session stores only its issue and its instance. Its workspace is (issue, instance's node), so nothing can disagree about where a session works, and an instance on another node simply means another workspace for the same issue.
  • Sub-agents are part of a session, like a tool call: something the agent does inside one conversation, so they can't point at another issue.
  • There are no sub-issues. Breaking work down is an issue's checklist or several issues; dependencies, if needed, become a relation between issues of one project.
  • An issue has one branch, the same on every node. A workspace is that branch checked out on one node; continuing elsewhere makes a workspace there from the branch.
  • A node has at most one copy of a project. Other clones on that machine aren't Conductor's.
  • Pairing, Copy and Workspace invent no ids: each is keyed by what it relates.

Rules the structure doesn't show

  • Every session belongs to an issue; a quick, unplanned session gets an issue made for it.
  • A workspace's node has a copy of the issue's project; the workspace is made from that copy.
  • A workspace runs one turn at a time, and is cleaned when its issue closes or after seven idle days. Uncommitted changes are checkpointed and the branch kept first.
  • The home never records where a node keeps anything; a node finds its copy of a project by root commit and remote.
